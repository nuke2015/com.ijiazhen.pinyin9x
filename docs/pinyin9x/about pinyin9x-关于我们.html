1.1 项目简介

九家输入法（Pinyin9x）是一款基于 Android InputMethodService 的九宫格中文拼音输入法。项目采用纯代码构建 UI（无 XML 布局），集成离线 SQLite 字典库、Sherpa-ONNX 流式语音识别、热句自动联想、数学公式计算等功能。

2.2 模块职责

PinyinIME（输入法主服务）

继承 InputMethodService，是整个应用的核心。负责：

  • 8 种键盘模式切换（拼音/QWERTY/符号/光标/数字/剪切板/收藏/设置）
  • 候选词栏的分页、展开、组词三步上栏
  • 语音输入的启停、动画、状态显示
  • 热句联想的触发、渐进式补全
  • 数学公式计算（递归下降求值器）
  • 热词学习（n-gram 提取 + 数据库 upsert）

PinyinEngine（拼音引擎）

纯静态工具类，核心能力是将九宫格数字串通过 DP 分段算法拆解为拼音音节组合，再结合 SQLite 字典库生成排序去重的候选词列表。

DictDBHelper + ClipDBHelper（数据层）

单例模式管理 SQLite 数据库。DictDBHelper 负责 chars/phrases/hot_sentences 三张表，ClipDBHelper 复用同一 SQLiteDatabase 实例管理 clipboard/favorites 两张表。

三、数据库文档

数据库文件 pinyin_dict.db 随 APK 的 assets 目录打包，首次启动时复制到应用私有目录。共管理 5 张表：2 张预构建只读表 + 3 张运行时创建可读写表。

5.5 热句联想交互

渐进式补全流程（以"你好"为例）

  1. 用户输入"你好" → 上屏 → tryTriggerHotSentence() 触发
  2. 查询 queryHotSentenceFull("你好") → 匹配到"你好，我们是家家月嫂，请问有什么可以帮您"
  3. 按标点分段：["你好", "我们是家家月嫂", "请问有什么可以帮您"]
  4. 候选栏显示下一段 hot "我们是家家月嫂"
  5. 用户选中 → 上屏 → onCandidateSelected() → hotSentenceIdx++
  6. 候选栏显示下一段 hot "请问有什么可以帮您"
  7. 用户选中 → 上屏 → 全部完成 → learnHotSentence() 频率 +1

5.6 热词自动学习机制

触发时机

用户在九宫拼音模式下手动输入汉字时，每次上屏的文本会追加到 manualInputBuffer 缓冲区。以下三种情况触发 splitAndLearn() 拆分学习：

  1. 标点输入：输入任何标点符号（逗号、句号、问号等）时立即触发，将缓冲区中已积累的汉字进行 n-gram 拆分学习。例如输入"育婴师，"后，逗号立即触发学习"育婴""婴师""育婴师"三个热词。
  2. 缓冲区溢出：缓冲区超过 200 字符时触发。
  3. 收起键盘：onWindowHidden() 回调时触发。

n-gram 拆分算法

// splitAndLearn() 核心逻辑
String text = manualInputBuffer.toString();
manualInputBuffer.setLength(0);
// 按标点分句
String[] sentences = text.split("[，。？！；：、…,!.?;:\\-\\s]+");
for (String sentence : sentences) {
    if (sentence.length() < 2 || sentence.length() > 10) continue;
    if (!isAllChinese(sentence)) continue;
    // 生成 2~4 字 n-gram
    for (int len = 2; len <= 4 && len <= sentence.length(); len++) {
        for (int i = 0; i + len <= sentence.length(); i++) {
            String ngram = sentence.substring(i, i + len);
            String digitSeq = PinyinEngine.toDigitSeq(ngram);
            db.upsertPhrase(digitSeq, ngram);  // freq +50
        }
    }
}

6.4 Paraformer 流式特殊处理

端点检测后补充尾部静音

Paraformer 流式模型在检测到端点（断句）时，需要补充约 0.8 秒的尾部静音 padding，确保最后一个词有足够的右上下文被正确识别。这是 sherpa-onnx 官方文档明确要求的特殊处理。

// 端点触发后
val tailPaddings = FloatArray((0.8 * SAMPLE_RATE).toInt()) // 0.8s 静音
stream.acceptWaveform(tailPaddings, SAMPLE_RATE)
while (rec.isReady(stream)) { rec.decode(stream) }
text = rec.getResult(stream).text
